## Reviewed contracts, model and dependencies

- Decoders require a readable three-/six-byte region; encoders require a writable
  region of that extent. Accessed objects have byte alignment, independently
  checked against genuine kernel headers. Getters reconstruct exact weighted
  byte sums and bounds. Stores accept every `u32`/`u64` value and specify each
  resulting byte; round trips recover the value modulo 2^24 or 2^48. No hidden
  input restriction is introduced to simplify proofs.
- The pointer-formation policy is explicitly `object-or-null`, separate from
  the recorded integer-arithmetic flags and Typed memory model. Actual audits,
  not just requested options, confirm the policy. Each byte group closes all
  12 ordinary and 12 exported pointer guards, including the final legal
  one-past pointer after a store. RTE-before-EVA calibration closes its three
  additional pointer guards. These are scoped results, not a claim that the
  unresolved MPI pointer guard or every project target passes.
- Promoted byte shifts by 8 and 16 are bounded by 16711680, within signed
  32-bit range. The 48-bit getter's larger shifts explicitly use `u64`;
  conversions and range conditions remain proved. TOD accepts the entire
  unsigned-long domain and proves `floor(todval * 125 / 512)` and a result no
  greater than the input, under the checked 64-bit model.
- The [run-local model](../results/pointer-policy-final-ci-20260906/suite/profile-s390x-gcc/profile.json)
  passes all 18 configured L1 checks. The genuine build uses
  `-march=z13 -mtune=z13`. Compiler/header fixtures check exact types, widths,
  byte alignment, the seven signatures and effective inline attributes.
  The independent wrong-width and wrong-endian controls reject their intended
  mismatches. Changing only the Frama-C YAML's native memory byte order also
  refutes the L1 model fixture's `byte_order_memory` assertion, not the BE24
  helper's endian-independent decode. Explicit-byte helper arithmetic alone
  would not establish that native-layout model property.
- The selected C call graph contains only the checked byte helpers and project
  witnesses; TOD is scalar and call-free. It has no trap, BUG, unreachable,
  assembly, MMIO, concurrency or indirect-call dependency. No trap stub is used
  to close these proofs. Broader selected-build trap behavior remains unchecked,
  so the compound trap-model milestone in A1 remains open.

The warning reviews remain bound to the exact source, strategies, genuine
header fixtures, model, preprocessing and analysis policy. They do not waive
an applicable pointer/alignment obligation or extend to unrelated functions.
The 12 and six smoke attempts for the byte groups remain inconclusive, not a
proof of consistency and not additional ordinary theorems. Kernel callers
remain responsible for the contracts' preconditions and are not verified here.

## Calibration and runtime boundary

The calibration retains all 16 positive selected properties. Its intentionally
false byte-order assertion remains raw `Invalid or unreachable`; this ambiguous
analyzer label alone is not a demonstrated invalid execution or a kernel bug.
The fresh [native receipt](../build/s390-sensitivity/native-4/receipt.json)
independently establishes that the bounded valid-input observations are reached:
the correct decode is true, the deliberately false claim is false, native
big-endian layout is observed, and execution returns normally.

The compiler and requested CPU are z13; the actual emulator CPU is explicitly
QEMU `max`. The failed exact-z13 startup is retained, not treated as a guest
execution. The pinned expoline return backend is trusted native support, not
a proved assembly or trap model. This one BE24 observation does not corroborate
all helper inputs, stores, 48-bit/TOD behavior, or full z13 fidelity; consequently
no whole-pilot L3 claim follows. Floating point, bit-field allocation, arbitrary
assembly, concurrency, MMIO and compatibility layouts remain outside scope.
