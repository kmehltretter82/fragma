# Common24 scoped modeling review

Decision date: 2026-09-06. Reviewer: Codex AI assistant, with an independent
AI source/operation review by `pointer_audit`. This is not a human approval.

The two assumptions `common24-types` and `common24-frontend` are reviewed
assumptions for exactly the four selected helpers and two project witnesses
under `arm-gcc`, `powerpc32-gcc` and `m68k-gcc`, at Linux
`b9b3e33b70b71e516930117e21de3ad2a7723747`. Their implementations are not marked
proved by this review. The individual warning reviews in the target manifest
have the same narrow scope and retain the actual diagnostics.

This decision does not supply a fresh proof, waive a missing obligation, certify
an old receipt under changed inputs, or award L2/L3. Every new run must pass its
current source, model, frontend, compiler-calibration, proof and dependency
gates. All 12 smoke checks per profile remain individually inconclusive unless
new evidence changes their raw outcomes. No smoke waiver is granted.

## Types and complete domains

The genuine configured-header fixture checks `u8` as exactly `unsigned char`
and `u32` as exactly `unsigned int`, eight-bit bytes, 32-bit `int` with
`INT_MAX == 2147483647`, `u8` alignment one and all four exact signatures.
The wrong-type control substitutes `unsigned long`, which has the same width
on these three profiles but is a different C type; all five intended type and
signature checks reject it. Width equality alone is not the justification.

The getters require only three readable bytes. Every byte promotes to a
nonnegative `int` in 0–255. The largest C shift is `255 << 16 == 16711680`;
the combined value is at most 16777215, within the checked signed-int range.
The C shift counts are fixed at 8 and 16; the decomposition annotations also
use 24, still below 32. The four exported `shift` obligations are
nonnegative-operand checks, not four separately exported count checks.

The writers accept every `u32` and require only three writable bytes. Their
right shifts are unsigned and masking constrains each stored value to 0–255.
There is no negative signed right shift or out-of-range stored-byte conversion.
The final post-increment forms one-past without dereferencing it. All selected
memory-access and pointer-formation obligations must remain present and valid.
The witnesses initialize all three local bytes through the writer before
reading them and promise `val % 16777216` for every `u32`.

No extra word alignment, `val <= 0xffffff`, extended storage extent or
host-endian restriction is introduced. Word-sized dereferences, `long`,
`size_t`, compatibility ABIs, kernel callers and other helpers are outside scope.

## Individual warning justifications

1. GNU inline: the exact genuine declaration prefix is retained and checked.
   The review permits abstraction of linkage/inlining attributes for these
   static sequential helper bodies and direct project-witness calls. It does
   not prove external linkage, instrumentation, timing or emitted instructions.
2. PowerPC `patchable_function_entry`: its exact `(0,0)` spelling comes from
   the actual configured macro branch. Retaining and checking it does not model
   entry patching or prove that this translation unit enables entry padding.
   The warning is reviewed only for the same sequential-C abstraction.
3. Unsupported alignment guards: every dereference is through `u8`, whose
   genuine alignment is one. There is no word load, pointer cast or stricter
   aligned type in the six bodies. This is not a waiver for other targets.
4. Unsupported indirect-call guards: the only calls are the four direct witness
   calls, whose precondition obligations must be proved. No indirect call is
   present. Compiler-only function-pointer typedefs check signatures and are
   never called.
5. Disabled signed-overflow reporting: the complete-domain range argument above
   covers every getter promotion/shift and writer conversion. The review does
   not claim that a disabled overflow guard was generated, and does not extend
   to another body or arithmetic policy.
6. Missing RTE guards: this is reviewed against the complete operation map,
   explicit arithmetic settings and retained obligations, not the analyzer's
   exit status. Installed Frama-C 33 `wpRTE.ml` excludes alignment and
   indirect-call categories from its missing-status list. Explicitly disabled
   arithmetic categories can set that status, and `cfgGenerator.ml` reports
   the earlier snapshot. The two unsupported-feature warnings are therefore
   not, by themselves, an explanation for Missing RTE.

The primary local implementation and manual files identified in the detailed
draft were inspected for these interpretations. The WP manual states that
smoke attempts are inconclusive when they do not establish inconsistency;
`reviewed_smoke` stays empty. Straight-line bodies and direct calls contain no
loop, recursion, trap, assembly or external implementation contract. This
review does not cover concurrency, MMIO, tracing or exceptional kernel behavior.

## Invalidation and acceptance

Each manifest review binds its exact profile/revision, toolchain lock, machine
description, source/build, analysis and preprocessing policies, proof search,
compiler-calibration setting, implementation hashes and inspectable evidence.
Warnings must match individually, with exact source locations where supplied.
No blanket diagnostic filter is added.

Changing a selected body, domain, signature, typedef, attribute policy, model,
build, calibration provider or required obligation requires renewed checks and
review. A passing finite compiler check cannot substitute for any missing
proof dependency. Architecture support, if subsequently established, remains
limited to these four kernel helpers under each explicitly checked profile;
the two witnesses do not increase the kernel-function count.
