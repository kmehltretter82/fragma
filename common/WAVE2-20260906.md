## RISC-V assertion numbering

The genuine headers emit two earlier `RISCV_ISA_EXT_MAX` compile-time assertions
before the calibration function. They consume `__COUNTER__` values zero and one,
so the 22 common24 assertions are named `__compiletime_assert_2` through
`__compiletime_assert_23`. The original diagnostic matcher expected zero through
21 and therefore rejected the first otherwise intended `decode_be` diagnostic.
The positive preprocessing and first negative raw output document this directly.

The implemented correction derives the exact ordered case-to-symbol mapping
from the unique calibration function in authenticated positive preprocessing,
then require that independent symbol in each negative diagnostic. The mapping
must retain all 22 labels, canonical unique consecutive numbers and one matching
call per declaration. It must not infer expectations from the error being checked,
hard-code a RISC-V offset, reset a kernel macro, or accept arbitrary diagnostics.
The fixed C, genuine compiler command and 22 wrong-value controls remain unchanged.

## Profile boundaries

ARM64 and RISC-V are LP64; SH is ILP32. Genuine `u32` is unsigned int on all
three. The wrong-type fixture substitutes unsigned long only in its expected
type/signatures: it differs in width as well as type on the two LP64 profiles,
but has the same width and a different type on SH. All five expected type and
signature errors remain required; the fixture does not redefine genuine `u32`.

ARM64 preserves its LP64/general-register/branch-protection settings. RISC-V
preserves LP64, medany, strict alignment, no-save-restore and the configured
attribute switches; the machine generator's musl headers are not used as kernel
headers. SH retains its ordered SH4/SH4A no-FPU options, little endian and
no-FDPIC setting. None of these observations proves emitted ISA, instrumentation,
runtime reachability, kernel callers or other ABI/configuration variants.

The following stages complete the diagnostic correction, regression checks,
missing RISC-V proof and profile-bound review. Fresh normal acceptance and
retained-evidence replay/coverage audit remain separate gates.

shared implementation changes require renewed current acceptance rather than
