# MIPS32el MT7621 configured profile

Status: **registered and passed L1; not L2 or L3**.

The production `mips32el-clang` profile now covers one precise Linux target:
MediaTek/Ralink MT7621, O32 little-endian MIPS32r2, soft-float compiler mode,
four-CPU SMP/CPS configuration, unsigned plain `char`, and two-byte kernel
`wchar_t`. Malta remains useful as a generic emulator/calibration board but is
not the production profile. The compact [result](../results/mips32el-mt7621-l1-20260907/SUMMARY.md)
binds the ignored raw build and model evidence.

## What passed

The normal no-override preparation path selected the pinned seed
`profiles/configs/mips32el-mt7621.config`, verified its SHA-256 before creating
the build, and built the genuine pinned-kernel `lib/string.c` translation unit.
The route requires the exact Clang/LLVM 21.1.8 tool suite and rejects a changed
ABI, endian mode, ISA, float mode, assembler route, platform include order,
ELF machine or MIPS ELF flags.

All 19 profile gates pass. They cover compiler/version/target/resource identity,
the authenticated musl generator headers, generated machine fields, target
macros, configured kernel types and layout, wrong-width and wrong-endian
controls, representative parsing, Eva arithmetic and memory-byte-order checks,
the explicit pointer-formation policy, negative model construction, and the
configured-kernel build. The model has 32-bit pointers, `int` and `long`,
64-bit `long long`, four-byte pointer/long alignment, eight-byte `long long`
alignment, and little-endian byte order.

The selected object is genuine ELF32 little-endian MIPS, machine 8, with flags
`0x70001001` (`noreorder`, O32, MIPS32r2). The exact Kbuild command contains
`--target=mipsel-linux-gnu -mabi=32 -EL -march=mips32r2 -msoft-float`, the
integrated assembler, `-G 0`, the kernel assembler forwarding, and the MT7621
platform include chain.

## Reproduce

With the previously authenticated musl 1.2.5 generator-header sysroot present:

```sh
python3 -m fragma prepare --profile mips32el-clang --jobs 8
python3 -m fragma.profiles \
  --profile mips32el-clang \
  --kernel /path/to/linux \
  --kernel-build build/kernel/mips32el-clang \
  --frama-c toolchain/verified-prefix/opam/fragma/bin/frama-c \
  --output build/profile-checks/mips32el-mt7621-l1-NEW
```

Both operations are workspace-local. No network access, target execution,
package installation or `sudo` is required.

The retained result is `run-3`. Intermediate `run-2` failed closed because the
genuine Kbuild command contains `-ffreestanding` twice; the final validator
permits only that known, semantically idempotent duplication while continuing
to reject duplicate ABI, endian, ISA and float-mode selectors.

## Boundary and next gate

L1 establishes the checked sequential C model and genuine configured build for
this exact profile. It does not establish arbitrary MIPS code, assembly, MMIO,
floating-point code, concurrency, big-endian MIPS, MIPS64, other ISA revisions,
hard-float userspace ABIs, kernel runtime behavior or hardware support. A fresh
source-gated proof suite is required for L2; independent MT7621 execution would
be required for L3. The additive central-lock change is reviewed separately in
[the lock-extension record](../docs/TOOLCHAIN-LOCK-MIPS32EL-20260907.md).
